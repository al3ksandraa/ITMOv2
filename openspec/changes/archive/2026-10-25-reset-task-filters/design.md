# Design

## Context
- Текущий фронтенд хранит локальное состояние: `state = { filter, sort, search, priority }` и перерисовывает список задач в `render()`.
- Обработчики `input/change/click` меняют соответствующие поля состояния и вызывают `render()`; сеть дергается только в `fetchTasks()` при инициализации и в действиях, меняющих данные задач.
- Выбор задач для массовых действий хранится только в DOM; любая перерисовка списка сбрасывает визуальный выбор.

## Goals / Non-Goals

**Goals:**
- Добавить кнопку «Сбросить фильтры», которая локально приводит `search`, `priority`, `filter` к базовым значениям.
- Сохранить текущую сортировку `sort`.
- Не выполнять сетевые запросы и не менять данные задач.

**Non-Goals:**
- Сохранение выбора чекбоксов при перерисовке.
- Добавление новых серверных эндпоинтов или изменение контракта API.

## Decisions

- Размещение кнопки: в панели поиска/фильтрации под гридом, как отдельная строка `.row actions`, чтобы не ломать двухколоночную сетку.
- Обработчик: устанавливает `state.search = ''`, `el.search.value = ''`; `state.priority = 'all'`, `el.priorityFilter.value = 'all'`; `state.filter = 'all'`; вызывает `render()`. `state.sort` не трогаем.
- Выбор чекбоксов: сохраняем текущую модель — перерисовка сбрасывает выбор. Это минимально инвазивно и соответствует существующему поведению рендера и комментариям «keep selection in DOM only».

## Risks / Trade-offs

- Риск неожиданности для пользователя: сброс фильтров также сбрасывает визуальный выбор задач. Митигируем через ожидаемую семантику перерисовки и явные сценарии в спецификации.
- Потенциальные гонки с массовыми действиями: сбор выбранных `ids` выполняется до перерисовки, как в текущей реализации; батчирование устойчиво к перерисовке.

## Migration Plan

- TDD: добавить падающие проверки наличия UI-элемента и e2e сценариев, затем минимальная реализация на клиенте.
- Нет миграции данных или серверных изменений.

## Acceptance Strategy

- Ограничение раннера: не изменять `scripts/check.sh` в рамках данного изменения.
- Автоматизировано: расширить `tests/check_ui_search_filter.py` для проверки наличия `#reset-filters`; этот тест уже вызывается раннером.
- Ручные проверки в apply: сценарии из спецификации (сброс полей, сохранение сортировки, отсутствие сетевых запросов, очистка выбора) валидируются через браузер/DevTools без использования Playwright MCP.
- Документация: обновить `docs/requirements.md`, отразив новый UI-контрол и его поведение.

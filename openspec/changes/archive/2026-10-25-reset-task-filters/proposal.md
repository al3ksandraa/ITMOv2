# Proposal

## Why

Пользователи применяют поиск, фильтр по приоритету и статусу для навигации по задачам. Часто требуется быстро вернуться к исходному виду списка без ручного очищения каждого поля и переключения кнопок. Кнопка «Сбросить фильтры» снижает трение и исключает лишние шаги.

## What Changes

- Добавить кнопку управления «Сбросить фильтры» в панель поиска/фильтрации UI (`public/index.html`).
- Обработчик на клиенте сбрасывает локальное состояние фильтров: `search`, `priority`, `filter`.
- Сохраняется текущая сортировка (`sort`), список задач перерисовывается локально.
- Не выполняются сетевые запросы, не меняются данные задач.
- Выбор задач чекбоксами остаётся как в текущей реализации: перерисовка списка сбрасывает выбор (см. Design → Decisions).

## Capabilities

### New Capabilities
- `ui/reset-task-filters`: Кнопка «Сбросить фильтры» возвращает список задач к виду «Все» без поиска и без фильтра по приоритету, не влияя на сортировку и данные.

### Modified Capabilities
- (none)

## Impact

- Фронтенд: `public/index.html` — добавление кнопки; `public/app.js` — обработчик, изменяющий локальное состояние и вызывающий `render()`.
- Тесты: добавить статическую проверку наличия `#reset-filters` и e2e сценарии поведения с Playwright MCP.
- Сервер/контракт API/модель Task: без изменений.

## Acceptance & Validation

Автоматизировано (scripts/check.sh):
- Статическое наличие UI-элемента `#reset-filters` будет проверено расширением существующего `tests/check_ui_search_filter.py` (раннер уже запускает этот тест).
- Проба готовности сервера без изменений.

Ручная проверка в apply (без изменений раннера):
- Сброс фильтров очищает поиск, ставит приоритет «Все» и статус «Все».
- Сортировка сохраняется: текущий порядок остаётся, включённый режим сортировки не меняется.
- Нет сетевых запросов при сбросе: подтверждается через DevTools/Network.
- Сброс очищает выбор чекбоксов задач (перерисовка списка).

# Handoff: Task Planner (Practice 04)

Состояние
- Фича A (поиск и фильтрация на клиенте) реализована:
  - UI: `#search` и `#priority-filter` на странице, фильтрация по подстроке title/description (регистронезависимо), фильтр по приоритету `all|low|normal|high`.
  - Реализация: клиентская, без изменений API. Логика в `public/app.js` внутри `render()`; поиск/фильтр обновляют состояние и переотрисовывают список.
- Фича B (массовые действия) реализована:
  - UI: кнопки `#bulk-complete`, `#bulk-delete` и чекбоксы `.select-task` у задач.
  - Реализация: последовательные вызовы существующих API для выбранных задач — `PUT /api/tasks/:id` (done=true) и `DELETE /api/tasks/:id`.
  - Поиск/фильтр остаются совместимыми с массовыми действиями.

### Фича: «Сбросить фильтры»
- UI: кнопка `#reset-filters` в панели поиска/фильтрации.
- Поведение:
  - Сбрасывает поле поиска и фильтр по приоритету к значениям по умолчанию; статус — «Все».
  - Сохраняет текущую сортировку (`state.sort` не изменяется).
  - Не выполняет сетевых запросов; изменения локальны, вызывается `render()`.
  - Перерисовка очищает визуальный выбор задач (чекбоксы `.select-task`).
- Проверки:
  - Автоматизировано: статический тест `tests/check_ui_search_filter.py` проверяет наличие `#reset-filters` и базовую логику обработчика (назначения и отсутствие сетевых вызовов/модификации данных).
  - Ручные сценарии: проверить значения контролов после нажатия, сохранение сортировки, отсутствие запросов к `/api/*`, очистку выборов чекбоксов.

### Фича: «Фильтр задач по сроку» (Spec Kit)

- UI: `#deadline-filter` — «Все», «Просроченные», «Сегодня», «Без дедлайна». Фильтр сочетается с поиском, приоритетом и статусом через логическое И.
- `overdue` исключает выполненные и использует строгое `deadline < now`; `today` использует локальные календарные границы `[начало дня, начало следующего дня)`; `no-deadline` принимает строго `null`.
- Общая логика: `public/filter.js`, подключённый перед `app.js`. Время вычисляется один раз на перерисовку; отдельного таймера нет.
- Доступность: select вложен в label «Срок». E2E-сценарий `16-keyboard-filter` проверяет Tab, стрелки/Home/End, сохранение фокуса после перерисовки и переход к сбросу/обратно.
- Сброс возвращает срок, приоритет и статус в «Все», очищает поиск и выбор задач, сохраняет сортировку. Дополнительных API-запросов нет.
- `#empty-state` показывается только после успешной загрузки пустой выборки; загрузка и её ошибка не маскируются под пустой результат.
- `datetime-local` преобразуется в UTC через `new Date(value).toISOString()` без повторного применения смещения зоны. Существующие сохранённые даты не мигрируются.
- Unit: `npm run test:deadline`. Сквозные проверки: `npm run test:e2e`. Проверка репозитория: `sh scripts/check.sh`.
- E2E использует реальный Chrome/Chromium и временную копию неизменённого сервера, создаёт задачи через существующий API; пользовательский файл данных не затрагивается. Установленный Chrome на Windows выбирается автоматически при отсутствии скачанного Chromium; для другой среды доступны `PLAYWRIGHT_CHANNEL` и `PLAYWRIGHT_EXECUTABLE_PATH`.
- Playwright — зависимость только для разработки. Сквозные проверки работают напрямую, без MCP; официальный Playwright MCP в `opencode.json` остаётся настроенным.

# Handoff: Task Planner (Practice 04)

Состояние
- Фича A (поиск и фильтрация на клиенте) реализована:
  - UI: `#search` и `#priority-filter` на странице, фильтрация по подстроке title/description (регистронезависимо), фильтр по приоритету `all|low|normal|high`.
  - Реализация: клиентская, без изменений API. Логика в `public/app.js` внутри `render()`; поиск/фильтр обновляют состояние и переотрисовывают список.
- Фича B (массовые действия) реализована:
  - UI: кнопки `#bulk-complete`, `#bulk-delete` и чекбоксы `.select-task` у задач.
  - Реализация: последовательные вызовы существующих API для выбранных задач — `PUT /api/tasks/:id` (done=true) и `DELETE /api/tasks/:id`.
  - Поиск/фильтр остаются совместимыми с массовыми действиями.

Источники
- Сервис: `practices/practice_04/task_planner`.
  - Сервер: `server.js` (Node.js 18+, без внешних npm-зависимостей). Статика из `public/`. Данные — `data/tasks.json`.
  - Фронтенд: `public/index.html`, `public/app.js`, `public/styles.css`.
  - Документы: `docs/style-guide.md` (правила для фичи A), этот файл `docs/HANDOFF.md`.
- Общие правила и контракт: корневой `AGENTS.md`.
- OpenCode / MCP / Hook:
  - Конфиг: `opencode.json` (skills.paths, MCP: playwright).
  - Hook-плагин: `.opencode/plugins/check-after-edit.js` — запускает `sh scripts/check.sh` после правок.
  - Скрипт проверки: `scripts/check.sh`.

Проверки
- UI-тест наличия элементов фичи A: `tests/check_ui_search_filter.py`.
- Скрипт `scripts/check.sh`:
  - Запускает UI-тесты.
  - Если установлен Node — поднимает сервер на свободном порту (`PORT`, по умолчанию 3100), ждёт `GET /api/tasks` = 200.
  - Завершает `PASS` при успешной проверке.
- E2E через Playwright MCP (ручной сценарий):
  - Открыть `public/index.html`, подменить `fetch('/api/tasks')` тестовыми данными.
  - Проверить, что поиск и фильтр по приоритету корректно уменьшают список задач.

Ограничения
- Публичный API стабилен (см. `AGENTS.md`): нельзя изменять контракты `/api/tasks` и `/api/tasks/:id`, формат `Task` и временные поля (ISO UTC).
- Фича A выполняется целиком на клиенте — не добавлять серверных эндпоинтов.
- Массовые действия используют существующие эндпоинты — не требуется серверная батч-операция.
- Не добавлять тяжёлые зависимости в сервер; приоритет — нативный Node.
- Следовать `docs/style-guide.md` перед изменениями UI фичи A.

Готово к передаче: код, тесты, runner, hook и документация актуальны. Следующие шаги — покрыть массовые действия простым статическим тестом наличия элементов (по аналогии с фичей A) и при желании добавить e2e-сценарий через Playwright MCP.

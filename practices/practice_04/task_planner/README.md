# Планировщик задач и дедлайнов

Простой сервис с фронтендом для составления списка задач и дедлайнов.

Функции:
- Добавление задач с названием, описанием, приоритетом и дедлайном
- Просмотр списка, сортировка по дедлайну
- Отметка выполнения, редактирование и удаление задач
- Локальное сохранение на сервере в `data/tasks.json`

## Интерфейс практики 8

Интерфейс использует Bootstrap 5.3.9 для кнопок (`btn`), полей (`form-control`), селектов (`form-select`), карточек (`card`), сообщений (`alert`) и индикаторов загрузки (`spinner-border`). CSS Bootstrap и лицензия MIT лежат в `public/vendor/`, общие цвета, типографика и отступы заданы в `public/styles.css`. [Файлы Bootstrap](public/vendor/) · [Стили](public/styles.css)

Заполните форму «Новая задача» и нажмите «Добавить задачу». Во время сохранения кнопка блокируется. После успеха задача появляется в списке и форма очищается. При сбое сохранения введённые значения остаются в форме, а при сбое загрузки списка доступна кнопка «Повторить».

Как запустить:
1. Требуется Node.js 18+ (без дополнительных зависимостей)
2. Варианты запуска:
   - Если установлен make: `make run`
   - Без make: из папки `task_planner` выполнить `node server.js`
3. Открыть: http://localhost:3000

Из корня репозитория сервер можно запустить командой `node practices/practice_04/task_planner/server.js`. Порт по умолчанию — `3000`. Другой порт задаётся переменной окружения `PORT`.

Подсказки:
- Windows PowerShell/CMD: перейдите в папку `practices/practice_04/task_planner` и выполните `node server.js`
- macOS/Linux: то же самое; остановка сервера — Ctrl+C

Полезные команды:
- `make run` — запустить сервер на 3000 порту
- `make reset` — очистить список задач (обнулить `data/tasks.json`)

Структура:
- `server.js` — минимальный HTTP-сервер и REST API (`/api/tasks`)
- `public/` — статические файлы фронтенда
- `data/tasks.json` — хранилище задач (JSON)

Заметки по данным:
- Дедлайн хранится в виде ISO-строки (UTC). В UI используется `datetime-local` в вашей локальной зоне. Конвертация выполняется на клиенте.

## Проверки интерфейса

Для тестов нужны Node.js 20+ и npm. Из корня репозитория выполните `npm ci`. Установите Chromium командой `npx playwright install chromium` или используйте установленный Chrome на Windows. Затем запустите следующие команды.

```sh
npm run test:planner
npm run test:deadline
npm run test:e2e
sh scripts/check.sh
```

`test:planner` проверяет форму и список задач в браузере. Проверки используют временную копию сервера с отдельными данными. Для `sh scripts/check.sh` нужны Bash, Python 3 и curl.

### Скриншотные тесты

После `npm ci` установите браузер из той же версии Playwright и запустите сравнение из корня репозитория.

```sh
node node_modules/@playwright/test/cli.js install chromium --only-shell
npm run test:visual
node node_modules/@playwright/test/cli.js show-report .cache/task-planner-visual-report
```

Пять тестов сравнивают семь PNG. Они охватывают десктопный и мобильный список задач, загрузку, пустой список, ожидание сохранения, успешное создание и ошибку сохранения. Данные, время, локаль, часовой пояс и размеры окна зафиксированы. Playwright отключает анимации и скрывает текстовый курсор на снимках. [Сценарии](../../../tests/task_planner_visual.spec.cjs) · [Эталоны](../../../tests/task_planner_visual.spec.cjs-snapshots/)

Эталоны сняты на Windows x64 в Chromium Headless Shell `153.0.8010.12` из Playwright `1.63.0`. Для одинаковой отрисовки используйте ту же ОС, браузер и системные шрифты. Имя файла включает платформу, поэтому у другой ОС свой набор эталонов.

При расхождении откройте HTML-отчёт и сравните вкладки **Expected**, **Actual** и **Diff**. Если изменение внешнего вида ожидаемо, после просмотра обновите эталоны командой `npm run test:visual -- --update-snapshots` и снова запустите `npm run test:visual`.

### Сценарий и демонстрация

Студент заносит срок сдачи лабораторной. Он заполняет название «Сдать лабораторную», описание «Проверить отчёт перед сдачей», выбирает высокий приоритет и вводит 1 декабря 2026 года, 18:00. После отправки видит сообщение «Задача добавлена» и карточку в списке. При перезагрузке задача снова загружается через `GET /api/tasks`.

Демонстрационный прогон выполнен в Chrome на реальном Node.js-сервере с отдельным `data/tasks.json`. Отправка с клавиатуры вернула `201`, повторный Enter во время ожидания оставил один запрос `POST`, а последующий `GET` вернул сохранённую задачу. Для кадров ожидания запросы удерживались в браузере. Для кадров ошибок подставлялся ответ `500`, а повторные попытки проходили через реальный сервер.

### Как использовался AI

- **v0 от Vercel, макет.** Запрос включал фразу «Создай интерактивный прототип „Планировщик задач“ для учебной практики». Также попросили переключатель состояний и мобильную версию. v0 предложил светлую тему, две колонки на широком экране и кадры состояний формы и списка.
- **Codex, интерфейс.** Один из запросов для реализации — «Доработай планировщик по утверждённому макету. Используй компоненты Bootstrap, подключи форму к текущему `POST /api/tasks` и заблокируй повторную отправку на время запроса». При разборе карточки уточнили расположение флажков. Чекбокс выполнения перенесли к названию, а массовый выбор получил отдельную видимую подпись «Выбрать» и доступное имя с названием задачи.
- **Codex и Playwright, тесты.** Один из запросов для проверки — «Проверь видимые состояния загрузки, пустого списка, успеха и ошибки. Удержи первый `POST` и проверь повторный клик и Enter». При разборе прогона обнаружили зависимость между тестами и разделили их хранилища. Дополнительно проверили отправку с клавиатуры при подменённом ответе `201`. Контрольные поломки подтвердили, что тесты обнаруживают исчезновение сообщения об ошибке и дублирование карточки.

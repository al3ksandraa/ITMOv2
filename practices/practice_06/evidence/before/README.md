## Повторение

Из `practices/practice_06/lab/`, Python 3.10+:

```bash
python3 -B audit_before.py
python3 -B record_tests.py
```

Обе команды поддерживают `--output <каталог>`; по умолчанию результат записывается сюда. Скрипт аудита предназначен для воспроизведения на исходной версии; после исправлений основным автоматическим критерием служат регрессионные тесты. `record_tests.py` возвращает обычный код unittest: 1 при обнаруженных проблемах, 0 при полном успехе. Он не переводит падения в `expectedFailure`.

Можно отдельно запустить `python3 -B -m unittest -v test_security` либо только поставляемый набор `python3 -B -m unittest -v test_service test_http`. При запуске исходных HTTP-тестов исключите loopback из прокси, например `NO_PROXY=127.0.0.1,localhost`.

Рабочий Windows-интерпретатор и точные команды приведены в отчёте. `make` в текущем PATH отсутствует, его цели не запускались.

## Изоляция

[audit_support.py](../../lab/audit_support.py) поднимает исходные `Shop` и HTTP handler в отдельном процессе на `127.0.0.1:0`, получает фактический порт через служебный stdout и использует прямой `http.client`. Указать чужой адрес нельзя. Каждый сценарий и каждый HTTP-регрессионный тест имеют отдельные БД, сессии и файловую песочницу. По stdin передаётся только команда завершения тестового процесса; HTTP API не расширяется.

В V-10 удаляется именно корень собственного одноразового Sandbox. Снимки до/после включены в доказательство. Штатное завершение каждого сценария и удаление временного каталога записаны в `server_shutdown`. Постоянный сервер на 8066 не атакуется. Файлы вне sandbox не читаются и не удаляются.

Для проверки XSS используются уже установленные Node.js, Playwright и Chrome. [audit_browser.cjs](../../lab/audit_browser.cjs) выполняет безопасный DOM-маркер и запрещает запросы страницы за пределы собственного loopback-origin. Если браузер недоступен, скрипт фиксирует ошибку проверки и не объявляет исполнение JS доказанным. В сохранённом запуске маркер выполнен.

## Формат

`V-XX.json` содержит:

- `server`: собственный PID, host, port и временный корень;
- `requests`: метод, точный target с query-параметрами, отправленные заголовки и тело UTF-8; статус, заголовки, точное текстовое тело ответа и разобранный JSON;
- `confirmed`: результат проверки воспроизведения;
- `effect`: наблюдаемый эффект, а при файловых операциях — снимки;
- `server_shutdown`: результат завершения и очистки.

Учебные пароли и токены сохранены намеренно как доказательство V-07. Они относятся только к синтетическим аккаунтам и уже завершённым процессам. Browser-запрос проверяется отдельно в `V-06.effect`; HTTP-транскрипт этого сценария также содержит сохранение отзыва и ответ HTML.

`H-09-context.json` и два `H-09-*-context.txt` фиксируют только доставку отзыва в контекст; модельные ответы отсутствуют. `OBS-01-resources.json` — малый ограниченный эксперимент роста коллекций. `OBS-02-audit.json` — наблюдение полей журнала. `CONTROLS.json` — работающие ограничения и безопасный отказ неизвестным инструментам.

Временные порты, PID, токены и метки времени могут отличаться при повторении. Постоянные ID проблем сохраняются. JSON-файлы и лог тестов — UTF-8.

# REPORT: Локальная модель и тестовые сессии

## Окружение и модель
- Хост: локальный Linux
- Аппаратное обеспечение: CPU 13th Gen Intel(R) Core(TM) i5-13500H; RAM 15Gi; GPU: отсутствует (инференс CPU)
- Ollama: 0.34.0 (`/snap/bin/ollama`)
- Доступные локальные модели (фрагмент): `qwen3.5:4b`, `itmo-agent:latest`, `itmo-chat:latest`
- Выбранная модель: `qwen3.5:4b` (квантизация: Q4_K_M)
- Длина контекста в тестах: ограничили до 4096 (см. opencode.json) для стабильности коротких сессий.
- Характеристики модели (по `ollama show qwen3.5:4b`): архитектура qwen35; параметры 4.7B; контекст 262144; embedding 2560; квантизация Q4_K_M; возможности: completion, vision, tools, thinking.

## Конфигурация OpenCode
- Файл: `lab/demo/opencode.json`
- Provider: `ollama` c `baseURL: http://localhost:11434/v1`
- model/small_model: `ollama/qwen3.5:4b`
- Модель в разделе `models`: "qwen3.5:4b" с лимитом `context: 4096`, `output: 1024`
- Агент `local-guide`: права только чтения (`read`, `glob`, `grep`), системный промпт из `repo-system.txt`
- Примечание о контексте: в `Modelfile.agent` задан `num_ctx 65536` для рабочих экспериментов; в `opencode.json` ограничили контекст до 4096 для стабильных коротких тестов. Это осознанное различие режимов.

## Верификация работоспособности
- Тестовый простой запрос: `opencode run -m ollama/qwen3.5:4b --agent local-guide "Скажи 'ok' одной фразой"`
- Сырой ответ: `ok`

## Вопросы и ответы модели
Эталоны см. комментарии; вопросы задавались по одному в отдельных сессиях через `opencode run`.

1) Как запустить тесты? Укажи файл-источник.
   - Сырой ответ модели:

     В файле **test_service.py** (строка 24) используется `unittest.main()`.

     Запуск:
     ```bash
     python test_service.py
     ```
   - Эталон: из `lab/Makefile` — `make test` вызывает тесты в `demo` (стр. 4–5); из `lab/demo/Makefile` — `python3 -m unittest -v` (стр. 2–3). Файл тестов: `lab/demo/test_service.py`.
   - Оценка: Частично верно (правильный фреймворк и файл-источник, но предпочтительный способ — `make test` или `python3 -m unittest -v`).

2) Что будет при пустом имени подписчика? Подтверди кодом.
   - Сырой ответ модели: Поскольку в директории /mnt/d/Documents/Vibecoding/ITMOv2/practices/practice_03/lab/demo отсутствуют файлы кода, проверить поведение при пустом имени подписчика невозможно.
   - Эталон: `service.py:5–6` поднимает `ValueError("empty name")`; `test_service.py:13–16` тестирует исключение.
   - Оценка: Неверно. Модель ошиблась в навигации по репозиторию.

3) Где реализован unsubscribe? Проверь предпосылку вопроса.
   - Сырой ответ модели: Предпосылка вопроса неверна. В репозиториуме нет никаких файлов или функций с названием `unsubscribe`.
   - Эталон: верно; в `service.py` только `subscribe`; тестов на `unsubscribe` нет.
   - Оценка: Верно.

4) Какая CI-система запускает тесты?
   - Сырой ответ модели: Сведения о CI-системе отсутствуют.
   - Эталон: верно; конфигураций CI в репозитории нет.
   - Оценка: Верно.

5) Сохраняются ли подписки после перезапуска процесса?
   - Сырой ответ модели:

     Состояние подписок **не сохраняется** после перезапуска процесса.

     **Доказательство из кода:**
     - В `service.py` (строка 1) объявлена глобальная переменная `subscribers`. Эта переменная хранится только в памяти запущенного процесса.
     - В `test_service.py` (строка 7) перед каждым тестом вызывается `subscribers.clear()`, что подтверждает, что состояние не сохраняется между запусками/тестами.

     Таким образом:
     1. **Подписки** добавляются в `subscribers` внутри одного процесса.
     2. **При перезапуске процесса** переменная и её содержимое теряются.

     Вопрос не решается на уровне файловой системы или диска в рамках данной практики — состояние сохраняется только оперативной памяти конкретного запуска скрипта.
   - Эталон: верно; `subscribers = set()` в памяти; README подтверждает.
   - Оценка: Верно.

## Ограничения и наблюдения
- Скорость: ответы приходят, но модель может промахиваться по файловой структуре; терпима для поочередных запросов.
- Контекст: лимит 4096 достаточен для небольшого репозитория; при увеличении контекста навигация могла бы быть стабильнее.
- Системный промпт `repo-system.txt` помогает краткости и ссылкам, но не предотвращает ложные отрицания при неудачных glob.
- Модель не имеет знаний о CI вне репозитория и корректно заявляет об отсутствии сведений.

- Qwen 3.5 4B (Q4_K_M) доступна локально, баланс качества/ресурсов приемлем для ноутбука.
- Простая интеграция с Ollama; минимальные правки `opencode.json`.

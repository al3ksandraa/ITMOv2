# Agreement: UI × Logic — task-deadline-filter

Фактический путь каталога фичи: `.specify/features/task-deadline-filter/`

| Вопрос | Позиция UI | Позиция Логики | Предлагаемое решение | Решение человека |
|---|---|---|---|---|
| Выполненные задачи в «Просроченных» | Классификация допускает пересечение, но UI-фильтр «Просроченные» не должен показывать выполненные | Overdue по времени; статус — отдельный предикат | «Просроченные» всегда исключает `done=true`, даже без активного статус-фильтра | Approved |
| Выполненные задачи в «Сегодня» | Может показывать выполненные в режиме «Сегодня» при статусе «все» | Today по дате, статус — отдельный предикат | Для «Сегодня» показывать в соответствии со статус-фильтром (все/активные/выполненные) | Approved |
| Границы дня и временная зона | Локальная дата пользователя; [00:00; 24:00) локально | boundariesOfToday(now) в локальной TZ | Зафиксировать локальные границы по Date.setHours(0,0,0,0) и +1 день; end эксклюзивно | Approved |
| Сочетание фильтров | Логическое И всех условий | Пересечение предикатов | Фиксируем AND; «Выполненные» + «Просроченные» даёт пустую выдачу | Approved |
| Пустая выдача | Текст «Нет задач по выбранным критериям» в зоне списка | Пустой результат фильтра | Зафиксировать текст и место; без дополнительных API-вызовов | Approved |
| Сброс | Возвращает deadline=all, очищает поиск/приоритет, снимает выбор; сортировка сохраняется | Не менять sort, прочие поля к дефолту | Зафиксировать текущее поведение reset; сортировку не трогать | Approved |
| Обновление результатов со временем | Без авто-таймера | now меняется при действиях | Пересчитывать «сейчас» при каждой перерисовке списка (изменение фильтров, действия с задачами) | Approved |
| Дедлайн сегодня, но время прошло | Невыполнённые попадают и в «Сегодня», и в «Просроченные» | today — по дате; overdue — по времени | Разрешить пересечение множеств; выполненные не входят в «Просроченные» | Approved |
| Null дедлайн | «Без дедлайна» показывает только `deadline === null` | no-deadline: `task.deadline === null`, без проверки производного Date | Совпадает, без расхождений | Approved |
| Равенство границ | Начало дня включительно, конец — исключительно | today: `>= start`, `< end`; overdue: `< now` | Фиксируем today: `>= startOfToday && < startOfTomorrow`; overdue: строго `< now` | Approved |

Итог: спецификации UI и логики и общий контракт приняты Product/человеком. Разрешено начинать реализацию в соответствии с этими документами.

Примечания
- Фильтрация только на клиенте, без новых API-вызовов.
- Контракт API и Task неизменны.
- Реализация начинается после утверждения этой таблицы и спецификаций.

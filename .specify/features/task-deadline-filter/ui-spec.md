# UI-спецификация: Фильтр по сроку (task-deadline-filter)

Фактический путь каталога фичи: `.specify/features/task-deadline-filter/`

## Элементы управления и подписи
- Панель фильтров: существующий контейнер, порядок контролов — Поиск (`#search`) → Приоритет (`#priority-filter`) → Срок (`#deadline-filter`). На узком экране допустим перенос.
- Новый контрол: `<select id="deadline-filter">` вложен в `<label>` с текстом «Срок», как у существующих фильтров.
  - Опции и подписи:
    - `<option value="all" selected>Все</option>`
    - `<option value="overdue">Просроченные</option>`
    - `<option value="today">Сегодня</option>`
    - `<option value="no-deadline">Без дедлайна</option>`
- Кнопка «Сбросить фильтры»: `#reset-filters` — при нажатии возвращает `#deadline-filter` к `all` и сохраняет текущую сортировку.
- Сообщение пустой выдачи: элемент в зоне списка, например `<div id="empty-state" hidden>Нет задач по выбранным критериям</div>`.

Доступность:
- Лейбл связан через вложенный select; это допустимая неявная связь HTML. Контрол имеет доступное имя «Срок». Отдельный атрибут `for` не требуется.
- Tab переводит фокус с приоритета на срок. Стрелки, Home и End изменяют режим и выдачу; фокус остаётся на селекте после перерисовки. Следующий Tab переводит фокус на сброс, Shift+Tab возвращает к сроку.

## Начальное состояние
- `#deadline-filter` = `all`.
- Кнопки статуса: `#show-all` активна; используется существующее состояние `state.filter = 'all'`.
- Список задач отображается исходя из текущих значений поиска, приоритета и статуса; дедлайн-фильтр не ограничивает выдачу.
- `#empty-state` скрыт.

## Действия пользователя и ожидаемое поведение
1. Изменение значения `#deadline-filter` → триггер рендера со следующими условиями:
   - `overdue`: включаются задачи с установленным дедлайном, строго меньше текущего момента времени (`deadline < now`). Выполнённые задачи всегда исключаются из этого режима.
   - `today`: включаются задачи, у которых локальная дата дедлайна совпадает с текущей локальной датой пользователя (`startOfToday <= deadline < startOfTomorrow`). Выполненные задачи отображаются согласно выбранному статус-фильтру.
   - `no-deadline`: включаются задачи, у которых `deadline === null`.
   - `all`: дедлайн не ограничивает выборку.
2. Сочетание с другими фильтрами:
   - Итоговый набор — пересечение условий поиска (title/description, регистронезависимо), приоритета, статуса выполнения (через `state.filter` и кнопки `#show-all|#show-active|#show-done`) и дедлайна.
3. Сброс фильтров (`#reset-filters`):
   - Устанавливает `#deadline-filter` в `all`.
   - Очищает поиск (`''`), возвращает приоритет и статус к `all`, снимает чекбоксы выбора задач.
   - Сохраняет текущую сортировку.
   - Не вызывает дополнительных запросов к API.

## Состояние пустой выдачи
- В панели списка после `#task-list` размещается `<div id="empty-state" role="status">Нет задач по выбранным критериям</div>`.
- Сообщение показывается только после успешной загрузки задач, если отфильтрованный список пуст; при непустой выборке скрывается. Ошибка загрузки не считается пустой выдачей.

## Взаимодействие с существующими фильтрами и сбросом
- Порядок предикатов не важен (пересечение), рекомендация по реализации: фильтр по дедлайну применять после поиска и приоритета для уменьшения объёма проверки дат.
- Правила сброса задаются пунктом 3 раздела «Действия пользователя и ожидаемое поведение».
- Все вычисления локальны для клиента; fetch-вызовы не инициируются.

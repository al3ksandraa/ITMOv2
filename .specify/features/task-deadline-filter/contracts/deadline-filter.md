# Контракт: Фильтр по сроку (task-deadline-filter)

Фактический путь: `.specify/features/task-deadline-filter/contracts/deadline-filter.md`

## Область действия
- Применяется к клиентской части `practices/practice_04/task_planner`.
- Не меняет публичный API и модель `Task` (deadline — ISO 8601 UTC или `null`).
- Фильтрация выполняется на клиенте, без дополнительных запросов к API.

## Значения режимов
- `all` — не ограничивает выборку по сроку.
- `overdue` — дедлайн установлен и строго меньше текущего момента времени (`deadline < now`). Выполненные задачи (`done === true`) всегда исключаются из результата этого режима.
- `today` — локальная дата дедлайна совпадает с текущей локальной датой пользователя: `startOfToday <= deadline < startOfTomorrow`. Выполненные задачи отображаются согласно выбранному статус-фильтру.
- `no-deadline` — `deadline === null`.

Примечание о пересечении: режимы — это независимые предикаты. Невыполнённая задача с дедлайном «сегодня, но временем в прошлом» одновременно удовлетворяет `today` и `overdue`; фактическая выдача зависит от выбранного режима фильтра.

## Входные данные
- Массив задач `Task[]`, где `Task` соответствует AGENTS.md: `id`, `title`, `description` — строки; `priority` — low/normal/high; `done` — boolean; `deadline` — ISO UTC или null; `createdAt`, `updatedAt` — ISO UTC.
- Состояние клиентских фильтров: `search` (строка), `priority` (`all|low|normal|high`), `filter` (статус `all|active|done`), `deadline` (`all|overdue|today|no-deadline`), `sort` (существующий режим `none|deadline`).
- Текущее время `now` (браузер), вычисляется при каждой перерисовке списка (изменение фильтров, действия с задачами и т.п.); отдельный авто-таймер не используется.

## Результат
- Отфильтрованный массив задач = логическое И всех условий: поиск ∧ приоритет ∧ статус ∧ дедлайн-режим.
- Специальное правило статуса для `overdue`: вне зависимости от выбранного статус-фильтра режим `overdue` исключает выполнённые задачи.

## Правила времени и временной зоны
- Дедлайны хранятся в UTC; сравнение выполняется в локальной TZ клиента: ISO-строка → `Date` → вычисление границ.
- «Сегодня»: границы дня в локальной TZ: `startOfToday` включительно и `startOfTomorrow` исключительно (`startOfToday <= deadline < startOfTomorrow`).
- «Просроченные»: строгое сравнение по времени: `deadline < now`.
- `now`, `startOfToday`, `startOfTomorrow` вычисляются на момент перерисовки списка.

## Правила сброса
- Кнопка «Сбросить фильтры»:
  - Устанавливает `deadline` = `all`.
  - Очищает `search`, возвращает `priority` к значению по умолчанию, снимает выбор задач (чекбоксы).
  - Возвращает статус (`state.filter`) к `all`.
  - Сортировка (`sort`) сохраняется без изменений.
  - Дополнительных запросов к API не выполняется.

## Граничные случаи
- `deadline === null` → соответствует `no-deadline` и не исключается режимом `all`; не соответствует `today` и `overdue`.
- `deadline === now` → не попадает в `overdue` (сравнение строгое), но может попасть в `today`, если входит в диапазон.
- Дедлайн «в последний момент дня» → включается в `today`, если `< startOfTomorrow`.
- Дедлайн «сегодня», время уже прошло → невыполнённые задачи удовлетворяют и `today`, и `overdue`; выполнённые — не попадают в `overdue`.
- Невалидная ненулевая дата в `deadline` (включая пустую строку) не соответствует `today`, `overdue`, `no-deadline`; режим `all` её не исключает. Значение в хранилище не переписывается.
- Изменение времени: пересчёт производится при любом событии, запускающем перерисовку; отдельный фоновой таймер не используется.

## Совместимость и ограничения
- Публичный API и формат `Task` не меняются.
- Фильтрация полностью на клиенте, без новых эндпоинтов/запросов.
- Не добавляются новые рантайм-зависимости.

## Псевдокод предикатов (для справки)
```
isOverdue(t, now):
  if t.done: return false
  if t.deadline == null: return false
  return new Date(t.deadline) < now

isToday(t, now):
  if t.deadline == null: return false
  [start, next] = boundariesOfToday(now)
  d = new Date(t.deadline)
  return d >= start && d < next
```

## UX-следствия
- Сообщение пустой выдачи: «Нет задач по выбранным критериям» в области списка.
- Значение `deadline` при сбросе — `all`; сортировка не меняется.

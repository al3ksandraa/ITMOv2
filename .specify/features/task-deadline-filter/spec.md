# Фича: Фильтр задач по сроку (task-deadline-filter)

Фактический путь каталога фичи: `.specify/features/task-deadline-filter/`

## Область и ссылки
- Источник правил: `AGENTS.md`, `.specify/memory/constitution.md`.
- Сервис: `practices/practice_04/task_planner` (Node.js, без внешних зависимостей).
- Контракт: публичный API неизменен; поле `Task.deadline` — ISO 8601 UTC или `null`.

## Цель
Добавить клиентский фильтр задач по сроку исполнения, комбинируемый с существующими поиском, фильтром приоритета и учётом статуса выполнения, без дополнительных сетевых запросов.

## Ограничения и совместимость
- Никаких изменений API, модели `Task` и сценариев `scripts/check.sh` и `docs/requirements.md`.
- Только клиентская логика поверх уже загруженных данных (`GET /api/tasks`).
- Не добавлять зависимости в рантайм сервиса.
- Кнопка «Сбросить фильтры» сохраняет текущую сортировку.

## Режимы дедлайн-фильтра (семантика)
- Все (`all`): не ограничивает по сроку.
- Просроченные (`overdue`): задачи, у которых `deadline` строго меньше текущего момента времени; выполнённые задачи исключаются из этого режима.
- Сегодня (`today`): задачи, у которых локальная календарная дата `deadline` совпадает с локальной датой «сегодня» пользователя (`startOfToday <= deadline < startOfTomorrow`). Выполненные отображаются согласно статус-фильтру.
- Без дедлайна (`no-deadline`): задачи, у которых `deadline === null`.

Примечания по TZ и времени:
- Сравнения выполняются в локальном времени пользователя с учётом того, что `deadline` хранится в ISO UTC. Парсинг ISO → объект `Date`, далее вычисления локальных границ дня.
- Для «Просроченные» — строгое сравнение по времени: `deadline < now` (строгое).
- Для «Сегодня» — сравнение по дате: `startOfToday <= deadline < startOfTomorrow` (начало дня включительно, начало следующего дня исключительно) в локальной TZ.

Граничные случаи:
- Невыполнённая задача «сегодня, но временем в прошлом» удовлетворяет и `today`, и `overdue`; режимы не являются непересекающимися категориями.
- Некорректный ненулевой `deadline`, включая пустую строку, не соответствует `today`, `overdue`, `no-deadline`; режим `all` не исключает такую задачу по сроку.

## Время пересчёта
- `now` вычисляется один раз на перерисовку списка.
- Перерисовку запускают загрузка задач, изменение поиска/приоритета/статуса/срока, сброс, сортировка, успешные CRUD и массовые действия.
- Отдельный фоновый таймер не используется.

## Комбинирование с существующими фильтрами
- Результат = пересечение условий: текстовый поиск (title/description, регистронезависимый) ∧ фильтр приоритета ∧ существующий статус-фильтр ∧ дедлайн-фильтр.
- Порядок применения не влияет на итог (чистые предикаты), но для производительности разумно сначала применять самые грубые фильтры.
- Следствие: сочетание «Выполненные» и «Просроченные» даёт пустую выборку.

## Сброс фильтров
- Кнопка «Сбросить фильтры» устанавливает `search = ''`, `priority = 'all'`, `filter = 'all'` (статус), `deadline = 'all'`.
- Выбор задач чекбоксами снимается; текущая сортировка сохраняется. Запросов к API нет.
- Смена режима срока также не меняет сортировку и относительный порядок оставшихся задач; без сортировки сохраняется исходный порядок.

## Состояние клиента (рекомендация по полям)
- `state.search: string`
- `state.priority: 'all'|'low'|'normal'|'high'`
- `state.filter: 'all'|'active'|'done'` (существующий статус-фильтр по кнопкам #show-all|#show-active|#show-done)
- `state.deadline: 'all'|'overdue'|'today'|'no-deadline'` (новое поле для фильтра срока)
- `state.sort: 'none'|'deadline'` (существующий режим сортировки; при сбросе не изменяется)

## Алгоритм фильтрации (псевдокод)
```
function applyFilters(tasks, state, now = new Date()) {
  const q = normalize(state.search);
  const pri = state.priority;
  const st = state.filter; // текущий статус-фильтр в коде
  const dl = state.deadline;

  const [startToday, startTomorrow] = boundariesOfToday(now);

  return tasks.filter(t => {
    const d = t.deadline ? new Date(t.deadline) : null; // ISO UTC → Date

    if (q && !matchesQuery(t, q)) return false; // текстовый поиск
    if (pri && pri !== 'all' && t.priority !== pri) return false; // приоритет

    if (st === 'done' && !t.done) return false; // статус
    if (st === 'active' && t.done) return false;

    // дедлайн-фильтр
    if (dl === 'overdue') {
      if (t.done) return false; // «Просроченные» исключает выполненные
      if (!d || !(d.getTime() < now.getTime())) return false;
    } else if (dl === 'today') {
      if (!d || !(d >= startToday && d < startTomorrow)) return false;
    } else if (dl === 'no-deadline') {
      if (t.deadline !== null) return false;
    }

    return true;
  });
}

function boundariesOfToday(now) {
  const s = new Date(now);
  s.setHours(0,0,0,0);
  const tmr = new Date(s);
  tmr.setDate(tmr.getDate() + 1);
  return [s, tmr]; // начало дня включительно, начало следующего — исключительно
}
```

## Пустая выдача
- Если после применения всех предикатов список пуст, показать сообщение «Нет задач по выбранным критериям».
- Сообщение реализуется отдельным элементом `<div id="empty-state" role="status">` непосредственно после `#task-list` в панели списка.
- Сообщение показывается только после успешной загрузки задач и при пустой отфильтрованной выборке; при непустой — скрывается. Ошибки загрузки не считаются пустой выдачей.

## Нефункциональные требования
- Все операции выполняются в памяти; не увеличивать количество вызовов `fetch`.
- Производительность: фильтрация линейная по числу задач; не сохранять дополнительные копии вне рендера.
- UX: контроль `#deadline-filter` имеет доступное имя «Срок» через связанный `<label>`. В текущей разметке select вложен в label; отдельный `for` не требуется.
- Клавиатура: Tab переводит фокус с приоритета на срок, стрелки/Home/End изменяют режим, перерисовка списка сохраняет фокус на селекте. Следующий Tab переводит фокус на сброс, Shift+Tab возвращает его к сроку.
- Размещение контрола срока: в панели фильтров, порядок — Поиск → Приоритет → Срок.

## Критерии приёмки
1. Каждый режим («Все», «Просроченные», «Сегодня», «Без дедлайна») корректно ограничивает список задач при любых комбинациях поиска, приоритета и статуса.
2. «Просроченные» включает только невыполнённые задачи с `deadline < now`.
3. «Сегодня» включает задачи с `startOfToday <= deadline < startOfTomorrow`; выполненные отображаются согласно статус-фильтру.
4. «Без дедлайна» (значение `no-deadline`) показывает только задачи с `deadline === null`.
5. При пустой выдаче отображается «Нет задач по выбранным критериям».
6. Сброс возвращает дедлайн-режим к «Все» и сохраняет сортировку; запросов к API не происходит.
7. Пересчёт времени соответствует разделу «Время пересчёта».
8. Публичный API и формат `Task` не изменены.
9. Контрол срока доступен с клавиатуры и сохраняет фокус при изменении выдачи согласно нефункциональным требованиям.

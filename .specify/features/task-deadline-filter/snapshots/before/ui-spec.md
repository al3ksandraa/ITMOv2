# UI-спецификация: Фильтр по сроку (task-deadline-filter)

Фактический путь каталога фичи: `.specify/features/task-deadline-filter/`

## Элементы управления и подписи
- Панель фильтров: существующий контейнер рядом с `#search`, `#priority-filter` и контролами статуса (если есть).
- Новый контрол: `<label for="deadline-filter">Срок</label> <select id="deadline-filter" name="deadline">`
  - Опции:
    - `<option value="all" selected>Все</option>`
    - `<option value="overdue">Просроченные</option>`
    - `<option value="today">Сегодня</option>`
    - `<option value="none">Без дедлайна</option>`
- Кнопка «Сбросить фильтры»: `#reset-filters` — при нажатии возвращает `#deadline-filter` к `all` и сохраняет текущую сортировку.
- Сообщение пустой выдачи: элемент в зоне списка, например `<div id="empty-state" hidden>Нет задач по выбранным критериям</div>`.

Доступность:
- Лейбл связан по `for`/`id`.
- Управление с клавиатуры и корректные фокусы сохраняются по аналогии с существующими контролами.

## Начальное состояние
- `#deadline-filter` = `all`.
- Список задач отображается исходя из текущих значений поиска, приоритета и статуса; дедлайн-фильтр не ограничивает выдачу.
- `#empty-state` скрыт.

## Действия пользователя и ожидаемое поведение
1. Изменение значения `#deadline-filter` → триггер рендера со следующими условиями:
   - `overdue`: задача включается, если `deadline` установлен и строго меньше текущего момента времени.
   - `today`: задача включается, если локальная дата `deadline` совпадает с локальной датой «сегодня» пользователя (в интервале [00:00, 24:00) локально).
   - `none`: задача включается, если `deadline === null`.
   - `all`: дедлайн не ограничивает выборку.
2. Сочетание с другими фильтрами:
   - Итоговый набор — пересечение условий поиска (title/description, регистронезависимо), приоритета, статуса выполнения (если есть) и дедлайна.
3. Сброс фильтров (`#reset-filters`):
   - Устанавливает `#deadline-filter` в `all`.
   - Очищает поиск, возвращает приоритет к значению по умолчанию, снимает чекбоксы выбора задач.
   - Сохраняет текущую сортировку.
   - Не вызывает дополнительных запросов к API.

## Состояние пустой выдачи
- Если после применения всех критериев список пуст, показывать `#empty-state` c текстом «Нет задач по выбранным критериям» и скрывать контейнер списка или отображать пустой контейнер без элементов.
- При изменении фильтров, возвращающем элементы в список, `#empty-state` скрывается.

## Взаимодействие с существующими фильтрами и сбросом
- Порядок предикатов не важен (пересечение), рекомендация по реализации: фильтр по дедлайну применять после поиска и приоритета для уменьшения объёма проверки дат.
- «Сбросить фильтры» не меняет сортировку, но снимает выделения задач (чекбоксы) и приводит фильтры к значениям по умолчанию.
- Все вычисления локальны для клиента; fetch-вызовы не инициируются.

## Вопросы, которые нужно согласовать с командой логики
- Граница между «Сегодня» и «Просроченные» для задач с дедлайном «сегодня, но временем в прошлом»: относить к «Просроченные» или считать частью «Сегодня»? Требуется единое правило.
- Точное определение «Сегодня»: [startOfToday; endOfToday) локально — ок? Подтвердить.
- Влияние фильтра статуса: подтверждаем ли, что дедлайн-фильтр не меняет поведение статус-фильтра и всегда применяется поверх него.
- Текст и точное место появления пустого состояния: соответствие текущим гайдлайнам UI.

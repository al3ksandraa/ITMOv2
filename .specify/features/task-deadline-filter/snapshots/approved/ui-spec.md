# UI-спецификация: Фильтр по сроку (task-deadline-filter)

Фактический путь каталога фичи: `.specify/features/task-deadline-filter/`

## Элементы управления и подписи
- Панель фильтров: существующий контейнер, порядок контролов — Поиск (`#search`) → Приоритет (`#priority-filter`) → Срок (`#deadline-filter`). На узком экране допустим перенос.
- Новый контрол: `<label for="deadline-filter">Срок</label> <select id="deadline-filter" name="deadline">`
  - Опции и подписи:
    - `<option value="all" selected>Все</option>`
    - `<option value="overdue">Просроченные</option>`
    - `<option value="today">Сегодня</option>`
    - `<option value="no-deadline">Без дедлайна</option>`
- Кнопка «Сбросить фильтры»: `#reset-filters` — возвращает фильтры к значениям по умолчанию и сохраняет сортировку.
- Сообщение пустой выдачи: `<div id="empty-state" role="status">Нет задач по выбранным критериям</div>` после `#task-list`.

## Начальное состояние
- `#deadline-filter` = `all`.
- Кнопки статуса: `#show-all` активна; используется существующее состояние `state.filter = 'all'`.
- Список задач отображается исходя из текущих значений поиска, приоритета и статуса; дедлайн-фильтр не ограничивает выдачу.
- `#empty-state` скрыт.

## Действия пользователя и ожидаемое поведение
1. Изменение значения `#deadline-filter` → триггер рендера:
   - `overdue`: `deadline < now`, выполнённые исключаются.
   - `today`: `startOfToday <= deadline < startOfTomorrow`; выполненные зависят от статус-фильтра.
   - `no-deadline`: `deadline === null`.
   - `all`: дедлайн не ограничивает выборку.
2. Сочетание с другими фильтрами: итог = поиск ∧ приоритет ∧ статус (`state.filter`) ∧ дедлайн.
3. Сброс (`#reset-filters`):
   - Очищает поиск; возвращает приоритет, статус и срок в `all`; снимает выбор задач; сортировку сохраняет; без API-запросов.

## Состояние пустой выдачи
- Отображать `<div id="empty-state" role="status">Нет задач по выбранным критериям</div>` только после успешной загрузки, если отфильтрованный список пуст. Скрывать при непустой выборке.

## Взаимодействие и согласованные положения
- Фильтры применяются как И; «Просроченные» всегда исключает выполненные; пересечение режимов допустимо (невыполнённые «сегодня и в прошлом» попадают в оба).
- Пересчёт «now» на каждую перерисовку; без таймера.

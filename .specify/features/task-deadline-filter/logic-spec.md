# Логика: Фильтр задач по сроку (task-deadline-filter)

Файл фиксирует правила клиентской логики в соответствии с принятыми решениями в `agreement.md` и контрактом в `contracts/deadline-filter.md`. Публичный API неизменен; реализация — на клиенте без дополнительных запросов.

## Модель Task: необходимые существующие поля
- `id: string`
- `title: string`
- `description: string`
- `priority: 'low'|'normal'|'high'`
- `deadline: string|null` — ISO 8601 UTC или `null`
- `done: boolean`
- `createdAt: string` — ISO 8601 UTC
- `updatedAt: string` — ISO 8601 UTC

## Режимы и точные правила
- `all` — дедлайн не ограничивает выборку.
- `overdue` — дедлайн установлен и строго меньше текущего момента (`deadline < now`), выполненные задачи всегда исключаются из результата этого режима независимо от статус-фильтра (`done === true` → исключить).
- `today` — локальная дата дедлайна совпадает с локальной датой «сегодня»: `startOfToday <= deadline < startOfTomorrow`. Выполненные задачи отображаются согласно выбранному статус-фильтру.
- `no-deadline` — `deadline === null`.

Разрешено пересечение множеств: невыполнённая задача с дедлайном «сегодня, но временем в прошлом» одновременно удовлетворяет условиям `today` и `overdue`; фактическая выдача зависит от выбранного режима.

## Учёт выполненных задач
- Общий статус-фильтр (все/активные/выполненные) применяется как отдельный предикат.
- Специальное правило для режима `overdue`: выполнённые задачи исключаются из результата даже при статусе «все».
- Для `today` выполненные/невыполненные отображаются в соответствии с выбранным статусом.

## Локальная временная зона пользователя
- Сравнения выполняются в локальной TZ клиента: ISO (`deadline`) → `Date` → вычисление границ дня.
- Границы «сегодня» считаются локально через `setHours(0,0,0,0)` и прибавление одного календарного дня; конец дня — эксклюзивно.

## Границы текущего дня и сравнение с текущим моментом
- `startOfToday` — локальное «сегодня 00:00:00.000».
- `startOfTomorrow` — локальное начало следующего дня.
- «Сегодня»: `startOfToday <= deadline < startOfTomorrow`.
- «Просроченные»: строго `deadline < now`.
- Значение `now` вычисляется при каждой перерисовке списка.

## Сочетание с остальными фильтрами
- Итоговый набор = логическое И всех условий: поиск (title/description, регистронезависимый) ∧ приоритет ∧ статус выполнения ∧ дедлайн-режим.
- Порядок применения не влияет на результат; для производительности целесообразно применять дедлайн-предикаты после поиска/приоритета.

## Сохранение порядка задач
- Фильтрация не меняет текущую сортировку. Кнопка «Сбросить фильтры» не трогает `sort`.
- При отсутствии сортировки сохраняется исходный порядок массива.

## Момент пересчёта результатов
- Пересчёт выполняется при каждой перерисовке списка: изменение контролов, добавление/редактирование/удаление задач, первичная загрузка.
- Дополнительный фоновый таймер не используется.

## Граничные случаи
- `deadline === null` соответствует `no-deadline` и не исключается `all`; не соответствует `today` и `overdue`.
- `deadline === now` не попадает в `overdue` (строгое сравнение), но может попасть в `today`, если входит в дневной диапазон.
- Значение ровно в `startOfToday` включается в `today`; ровно в `startOfTomorrow` — нет.
- Дедлайн «сегодня, время прошло»: невыполнённые — удовлетворяют `today` и `overdue`; выполнённые — не попадают в `overdue`.
- Невалидная дата в `deadline` (если встретится) не попадает ни в `today`, ни в `overdue` и не считается `no-deadline` (контракт предполагает валидные ISO или null); рекомендуется исключать такие задачи из выдачи при применении дедлайн-фильтра.

## Псевдокод (референс)
```
function boundariesOfToday(now) {
  const start = new Date(now);
  start.setHours(0, 0, 0, 0);
  const next = new Date(start);
  next.setDate(next.getDate() + 1);
  return [start, next];
}

function isOverdue(t, now) {
  if (t.done) return false;
  if (t.deadline == null) return false;
  const d = new Date(t.deadline);
  return d.getTime() < now.getTime();
}

function isToday(t, now) {
  if (t.deadline == null) return false;
  const [start, next] = boundariesOfToday(now);
  const d = new Date(t.deadline);
  return d >= start && d < next;
}
```

## Неизменяемые ограничения
- Публичный API и формат `Task` не меняются.
- Фильтрация полностью на клиенте; новые эндпоинты и зависимости в рантайме сервиса не добавляются. Зависимости только для разработки и проверок допускаются.
- Текст пустой выдачи: «Нет задач по выбранным критериям». Сброс устанавливает `deadline=all` и не меняет сортировку.

## Сброс (детализация)
- При нажатии «Сбросить фильтры» клиент должен:
  - Установить `deadline` = `all`.
  - Очистить поиск и вернуть приоритет к значению по умолчанию.
  - Привести статус к «все» (в текущем коде: `state.filter = 'all'`).
  - Снять выделения задач (чекбоксы выбора для массовых действий) в DOM.
  - Не изменять текущую сортировку (`sort`).
